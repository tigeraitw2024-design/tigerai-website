# 官網接 Google：你要做的事

官網要寄信、要收名單、要讀行事曆算出可預約時段。這三件事都靠一支小程式
（`Code.gs`）掛在**一個** Google 帳號上。

> **先回答你最在意的那題**：對，只要**一個**帳號有權限就夠了。
> 官網只會用這一個帳號，它看得到誰的行事曆，官網就避得開誰。
> 下面第 5 節講這個權限要怎麼拿到——如果公司用的是 Google Workspace，
> 管理員設定一次，全公司一次到位，沒有人需要自己動手。

做完把這些給我：

1. Apps Script 的網址（`.../exec` 結尾）
2. 你設的密語
3. 試算表的網址
4. 要避開的行事曆 ID（通常就是同事的 Google 信箱，一行一個）

---

## 1. 開一個官網專用的 Google 帳號

不要用你的主帳號。這支程式是用「帳號擁有者的身分」在跑，所以它有權限讀寫
那個帳號的**所有信件、試算表、行事曆**。網址萬一外流，波及範圍就只有這個
專用帳號，不會碰到你自己的信。

建議的名字：`tigerai.web@...` 這類看得出用途的。

**你自己要看得到資料，用「分享」就好，不要共用帳號：**

- 試算表 → 右上「共用」→ 加你的公司信箱
- 行事曆 → 設定 → 與特定使用者共用 → 加你的公司信箱，權限給「變更活動」

這樣所有預約都會出現在你自己的 Google 日曆裡，但程式碰不到你的帳號。

## 2. 開試算表

用專用帳號開一份空白試算表，名字取「官網名單」。

不用自己做標題列，程式第一次寫入時會自己建。

網址長這樣，中間那段就是 ID：

```
https://docs.google.com/spreadsheets/d/【這一段是 ID】/edit
```

## 3. 貼上程式

1. 用專用帳號登入 <https://script.google.com>，按「新增專案」
2. 把編輯區裡原本的東西全部刪掉
3. 把 `Code.gs` 整份貼進去
4. 改最上面那三行：
   - `SECRET` — 隨便打一串長一點的亂碼（這就是「密語」，見下面）
   - `SHEET_ID` — 第 2 步那段 ID
   - `CALENDAR_ID` — 留空就用這個帳號的主行事曆，通常留空就好

### 密語是什麼

Apps Script 部署出來的網址，Google 不會幫你加鎖——任何人知道那串網址，
就能叫它寄信、寫你的試算表。所以程式自己加了一道：**每一個請求都要附上
一串只有你和官網知道的字**，不對就直接回「bad secret」什麼都不做。

- 那串字你自己隨便編，越長越亂越好（例如 `tg-web-9f3k-xQ72-mm41-zzb8`）
- 填在 `Code.gs` 的 `SECRET`，同一串給我，我放進 Cloudflare 的密鑰區
- 你不用記它。寫在便條紙上、給我一次，之後就不會再用到

把網址想成門牌、密語想成鑰匙。門牌誰都看得到，但沒鑰匙打不開。

## 4. 兩個設定，漏了就不會動

**a. 時區**

左邊齒輪「專案設定」→ 時區改成 `(GMT+08:00) Taipei`。

不改的話算出來的可預約時段會差八小時，而且**不會報錯**，你只會看到時間很怪。

**b. 啟用行事曆的進階服務**

左邊選單「服務」→ 按 ＋ → 選「Google Calendar API」→ 識別碼保持 `Calendar`
→ 新增。

算空檔用的是 Google 的 FreeBusy 功能，要開這個才有。沒開的話，後台按
「現在重算時段」會直接告訴你這一步沒做。

## 5. 讓官網看得到大家的行事曆

這是你問的重點。官網只用那一個專用帳號，所以問題只有一個：
**怎麼讓這個帳號看得到 Morris、CEO、其他同事的行事曆。**

官網只需要知道「這個時段他有事」，**不需要知道他在開什麼會**。
所以權限只要給最低的那一級就好，這也讓大家比較願意點頭。

### 路線 A：公司用 Google Workspace（信箱是公司網域）

管理員（如果是 Morris 管的就找他）在 Google 管理控制台設定一次，全公司一次到位：

```
管理控制台 → 應用程式 → Google Workspace → 日曆
  → 共用設定 → 內部共用選項
  → 設成「僅限空閒／忙碌資訊」或更開放
```

這樣同網域的帳號彼此就看得到忙閒，**沒有任何人需要自己操作**。
你只要把每個人的信箱填進後台「還要避開誰的行事曆」就好。

### 路線 B：大家用的是各自的 Gmail（不同網域）

Google 沒有「一次給一個帳號看所有人」的開關——這是 Google 的權限規則，
不是程式的限制。每個人要自己分享一次，之後永遠有效：

```
Google 日曆 → 左邊自己的行事曆 → 三個點 →「設定和共用」
  →「與特定使用者或群組共用」→ 加【官網專用帳號】
  → 權限選「僅顯示空閒／忙碌資訊（隱藏詳細資訊）」
```

一個人大概 30 秒，做一次就好。

### 然後

把要避開的人的行事曆 ID（通常就是他的 Google 信箱）填進後台
「預約時段規則 → 還要避開誰的行事曆」，一行一個。

填了但對方還沒分享也不會壞：後台按「現在重算時段」會明確告訴你
**哪一個讀不到、為什麼**，前台照樣排得出時段，只是那個人的行程沒被避開。

### 整天的行程（出差、休假）

不用在後台設定。Google 日曆上每個活動本身就有「忙碌／空閒」，官網照那個算。

- 出差整週 → 在 Google 日曆把那個活動設成**忙碌** → 那幾天約不到
- 生日、國定假日提醒 → 保持**空閒**（Google 的預設）→ 不影響

這樣可以一個行程一個行程決定，比一個全站開關準。
注意 Google 的整天活動**預設是「空閒」**，要擋就要自己改成「忙碌」。

## 6. 部署

右上「部署」→「新增部署作業」→ 類型選「網頁應用程式」：

| 欄位 | 要選什麼 |
| --- | --- |
| 執行身分 | 我自己 |
| 具有存取權的使用者 | **任何人** |

「任何人」聽起來很可怕，但那只是讓 Cloudflare 打得到。真正的門是你設的密語。

第一次會跳出授權畫面（Google 會說「這個應用程式未經驗證」，因為是你自己寫的），
按「進階」→「前往…（不安全）」→「允許」。

部署完會給你一個 `https://script.google.com/macros/s/.../exec` 的網址。

> ⚠ **以後每次改 `Code.gs` 都要重新部署**：
> 「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本改成『新版本』→ 部署」。
> 只按儲存不會影響線上，這是 Apps Script 最常踩的坑。

## 接起來之後會怎麼運作

```
公司每個人照常用自己的 Google 日曆
    ↓
官網每小時問一次 Google：「這些人在未來兩週分別什麼時候是忙的？」
（只拿到忙閒時段，拿不到會議內容）
    ↓
照你在後台設的規則（上班時間、一天幾場、要提前幾小時、兩場之間空多久）
扣掉忙碌的時間，算出可預約時段
    ↓
客戶在官網上選一個時段、填資料、送出
    ↓
官網當場再問一次「這個時間還空著嗎」（避免剛剛有人排了別的事）
    ↓
在行事曆上開一格、寄一張行事曆邀請給客戶
同時寫一列進「官網名單」試算表
    ↓
客戶按「是」 → 後台自動變「已確認」，這場也進了他的手機行事曆
客戶按「否」 → 後台變「客戶婉拒」，時段放回去
24 小時都沒按 → 自動取消，行事曆上那一場也撤掉，時段放回去
    ↓
CRM 每兩小時從試算表抓名單進去，標「來源＝官網」
```

交易信（預約確認、訂單通知）官網自己即時寄。行銷信交給 CRM。

## 設定好之後在後台哪裡看

**總覽**那一頁會多兩塊：

- **Google 中繼站**：現在用什麼方式寄信、名單同步開了沒、「測試連線」按鈕
  （只打一下招呼，不會寄信也不會寫試算表）、待送出／送不出去的名單
- **可約時段**：來源是手動還是行事曆、現在有幾個未來的時段、
  「現在重算時段」按鈕（有人改了行程，按一下就馬上反映到前台），
  以及哪些行事曆讀不到

**預約時段規則**那一頁（左邊選單「生意」底下）可以改所有規則，不用找我。

## 免費額度

| 項目 | 免費帳號 | 夠不夠 |
| --- | --- | --- |
| Gmail 寄信 | 每天 100 封 | 預約確認信綽綽有餘 |
| Apps Script 執行 | 每天 90 分鐘 | 每小時算一次 × 幾秒 = 一天不到 3 分鐘 |
| 行事曆、試算表 | 沒有實際上限 | — |

寄信超過額度不會掉信：信留在佇列裡，下一輪再試，後台的「待寄出的信」
會看得到。
